El prototipo que nunca sale del notebook

Los agentes de inteligencia artificial basados en modelos de lenguaje pasaron de ser experimentos a ser componentes reales de procesos empresariales: atención al cliente, calificación de oportunidades comerciales, generación automática de documentos.

💡 La brecha que aborda este webinar

Construir un agente que funciona en un cuaderno de pruebas es una cosa. Desplegarlo de forma segura, escalable y monitoreada en un entorno de producción real es otra muy distinta — y es justamente esa segunda parte la que casi nunca se enseña junto con la primera.

¿Qué es un agente de inteligencia artificial?

No es simplemente "hacerle una pregunta a un modelo de lenguaje". Es un sistema que percibe una entrada, decide qué hacer y actúa para cumplir un objetivo — de forma repetida, a lo largo de una conversación completa.

🤖 Agente racional

"Un agente racional selecciona la acción que se espera maximice su medida de desempeño, dado su conocimiento previo y la evidencia percibida." — Russell & Norvig (2021)

💬 Con un modelo de lenguaje, el agente además consulta información externa y mantiene memoria de la conversación

Orquestación: el agente como un grafo de estados

Un agente real no es una sola llamada al modelo: es una secuencia de pasos que dependen unos de otros, y que debe recordar en qué punto de la conversación está.

Nodo — cada paso del razonamiento (extraer un dato, consultar el catálogo, generar la cotización).
Transición — la regla que decide a qué nodo pasar según lo que respondió el usuario.
Memoria (checkpoint) — el estado de la conversación se guarda entre mensajes, para no perder lo ya recopilado.
📊 Frameworks como LangGraph modelan esto como un grafo dirigido de nodos y transiciones

Así se lo pide uno al modelo

En cada turno, el agente arma un prompt con el catálogo, lo que ya sabe del cliente, lo que falta por preguntar y el historial reciente — y le pide al modelo una salida estructurada, no texto libre. Esto es lo real, de app/extraction.py:

Eres un agente comercial que cotiza equipos médicos. Catálogo disponible: {listar_catalogo_texto()} Datos ya conocidos del cliente: {contexto_conocido} Campos que aún faltan por completar (en orden): {campos_faltantes} Nuevo mensaje del cliente: "{mensaje}" Actualiza SOLO los campos que el nuevo mensaje aporte (no inventes datos que no fueron mencionados). Redacta una respuesta breve, cordial y consultiva en español.
📦 La respuesta llega validada con Pydantic — nada de parsear texto con regex

Amazon Web Services es el proveedor de nube más usado del mercado: tiene un servicio dedicado para casi cualquier necesidad de una aplicación en producción.

🌐 CloudFront — entrada pública / CDN 📦 ECR — registro de imágenes 🚀 ECS Fargate — cómputo sin servidores ⚖️ ALB — balanceo de carga 🔐 Secrets Manager — credenciales 📈 CloudWatch — logs y alarmas

La ruta rápida: CloudFront

CloudFront es la red de distribución de contenido (CDN) de AWS. Además de entregar contenido desde ubicaciones cercanas a cada usuario, puede actuar como proxy HTTPS hacia cualquier origen — incluido un backend que corre fuera de AWS.

⚠️ El detalle que rompe el despliegue

Si el origen es una plataforma multi-tenant (Render, Vercel...), la política de origin request debe ser Managed-AllViewerExceptHostHeader, no AllViewer — de lo contrario CloudFront reenvía el Host equivocado y la plataforma responde 502.

💰 CloudFront tiene una capa gratuita permanente: 1 TB + 10M solicitudes/mes

La ruta completa: contenedores en producción

ECR — registro privado donde se publica la imagen Docker.
ECS Fargate — ejecuta el contenedor sin administrar servidores.
Application Load Balancer — reparte el tráfico y expone un DNS público estable.
Secrets Manager + CloudWatch — credenciales seguras, logs y alarmas.

💵 Esta ruta no es gratis

El ALB tiene un costo fijo (~USD 16-20/mes) incluso sin tráfico, y Fargate cobra por cómputo reservado. Conviene cuando el tráfico esperado justifica ese gasto — no para una demo puntual.

El detalle que nadie cuenta: la facturación

Habilitar cualquier servicio de cómputo en GCP —incluido Cloud Run— exige una cuenta de facturación activa vinculada al proyecto, aunque el uso se mantenga dentro de la capa gratuita.

⚠️ Nota práctica

Si el despliegue falla con Billing account for project ... is not found, la causa habitual es una cuenta de facturación cerrada — se resuelve reactivándola o vinculando una nueva antes de reintentar.

GitHub no es solo un respaldo del código

GitHub aloja el código con control de versiones, pero en un despliegue moderno cumple un segundo rol: es la fuente de verdad desde la que las plataformas de hosting construyen y publican la app automáticamente.

El código (con su Dockerfile) vive en un repositorio.
Cada git push notifica a la plataforma de hosting.
La plataforma clona, construye la imagen y la publica sola.
🔄 Esto es CI/CD: integración y despliegue continuos, sin servidor propio

De un push a una URL pública

Render construye y sirve la misma imagen Docker directamente desde GitHub, sin pasar por ningún proveedor de nube tradicional.

Crear una cuenta gratuita en render.com — no pide tarjeta.
"New Web Service" → conectar el repositorio.
Render detecta el Dockerfile y construye la imagen sola.
Cada git push siguiente dispara un nuevo despliegue.

ⓘ Anexo

Glosario de términos

Agente de IA
Sistema de software que usa un modelo de lenguaje para interpretar entradas, razonar sobre ellas y ejecutar acciones orientadas a un objetivo.
Orquestación
Mecanismo que define y controla la secuencia de pasos y estados por los que atraviesa un agente durante una conversación.
API REST
Interfaz que permite la comunicación entre el agente y otros sistemas mediante solicitudes HTTP estandarizadas.
Contenerización
Empaquetado de una aplicación y sus dependencias en una unidad estándar que garantiza su ejecución consistente en cualquier entorno.
CI/CD
Integración y despliegue continuos: cada cambio en el código dispara automáticamente una construcción y publicación nueva.
Puesta en producción
Paso de una aplicación de un entorno de desarrollo local a estar disponible de forma estable, monitoreada y accesible para usuarios reales.

Fuentes ampliadas: Russell & Norvig (2021) · Beck (2004) · Vaswani et al. (2017) · Sculley et al. (2015) · Newman (2021) · Gartner (2025).
